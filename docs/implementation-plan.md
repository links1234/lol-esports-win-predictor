# Phased implementation plan

## Phase 0 - Recovery, audit, and contracts

Status: complete for the version 2 branch.

Acceptance criteria:

- The protected legacy checkout is not mutated.
- A credential-safe recovery snapshot preserves its source and configuration deltas.
- Every legacy repository has an explicit preserve, discard, and do-not-reuse assessment.
- The committed Riot credential is flagged for immediate rotation without being opened or copied.
- Architecture defines exact time boundaries, split roles, artifact contents, and prediction JSON.

## Phase 1 - Complete synthetic vertical slice

Status: complete.

Acceptance criteria:

- A modern `pyproject.toml` package exists under `src/lolpredictor`.
- Dependencies are locked.
- A deterministic synthetic professional-draft fixture builds a DuckDB database.
- Canonical records are schema-validated before insertion.
- Historical features are generated by state replay with strict-before provenance.
- Automated tests cover future perturbation, same-timestamp isolation, pre-update Elo, preprocessing boundaries, and chronological splits.
- Base-rate, Elo-only, logistic-regression, and gradient-boosted-tree candidates train successfully.
- The best candidate is selected only by validation log loss.
- All candidates receive chronological validation and test metrics.
- Reports include log loss, Brier score, calibration, ROC-AUC, accuracy, sample counts, and time, patch, and league breakdowns.
- A self-describing artifact and point-in-time feature snapshot are saved outside Git.
- A fresh process loads the artifact and predicts a JSON draft.
- Unit, integration, and end-to-end tests pass in CI.
- Linting, formatting, type checking, and credential guards pass.

## Phase 2 - Public historical data ingestion

Status: complete for Oracle's Elixir research ingestion and the pinned 2020-2026 Leaguepedia current-source workflow.

Scheduled refresh automation remains release work.
Tournament-tier metadata is present, but the eligible population currently has no tier variation.

Acceptance criteria:

- Pinned Leaguepedia and Oracle's Elixir schema adapters stage source files without committing them.
- Source URL, retrieval time, checksum, license metadata, and row counts are recorded.
- Stable team and player identity tables replace source-specific names.
- Duplicate games, roster inconsistencies, invalid drafts, missing timestamps, and patch anomalies produce quarantine records.
- The synthetic workflow and contracts remain unchanged.
- A documented data-quality report is generated before any model training.
- Only explicit pre-game allowlists plus the target result label are read from public sources.
- Mutating source gold, kills, objectives, duration, and other post-game columns cannot change canonical records or features.

## Phase 3 - Rolling temporal backtesting and calibration

Status: complete for the baseline framework and the July 2026 release cycle.

The combined logistic candidate failed the fixed LPL robustness gate, so the production recommendation remains Elo.
A changed model now requires a new untouched post-July 2026 holdout.
The follow-up native, Platt, monotone beta, and isotonic comparison is complete and documented in `docs/v3-calibration-results.md`.
It can produce only a warned development artifact because every 2026 interval in the current snapshot has already been opened.

Acceptance criteria:

- Expanding-window or rolling-window backtests span multiple seasons.
- No fold shares future-derived preprocessing or feature state with an earlier fold.
- Calibration methods are compared on chronological calibration intervals.
- Metrics include bootstrap uncertainty and minimum sample thresholds.
- League, patch, tournament stage, unknown-entity, and data-age slices are reported.
- Model promotion requires stable validation and holdout log-loss improvement over base rate and Elo.
- The promoted model records the exact public-data cutoff and source checksums.
- Map side and first-pick order are modeled independently for 2026 First Selection.
- Series score and Fearless Draft history contain only games completed before the target game.

## Phase 3B - Broadcast screenshot extraction

Status: complete for the deterministic vertical slice and the rights-aware grouped corpus benchmark tooling.

Real broadcast frames, target profiles, and a passing recording-grouped holdout remain release work.

Acceptance criteria:

- A versioned overlay profile defines only team, champion, and optional ban crop regions.
- A versioned template catalog provides canonical labels and content checksums.
- Every extracted field has confidence, runner-up evidence, and an accept or review disposition.
- Low-confidence required fields never produce a win probability without confirmation.
- Screenshot context forbids all in-game fields.
- Unrelated or in-game pixels outside configured regions cannot change the parsed draft.
- Parser accuracy is measured on match-grouped and recording-grouped holdouts.
- Source rights, checksums, resolutions, recording groups, match groups, and verified labels are required for every real frame.
- Automatically accepted team and champion fields reach 99.5 percent precision on grouped holdouts.
- Exact ten-champion accuracy reaches 95 percent for every supported profile.
- Unsupported layouts have zero automatic false acceptances.
- The complete synthetic image-to-prediction path runs in CI.

## Phase 3C - Partially pooled regional strength

Status: complete for development and shadow prediction.

The selected regional ensemble improves the matched v3 rolling control, but its opened 2026 calibration error fails the fixed target.
The eligible population contains no tournament-tier variation, so no tier effect was estimated.
Promotion still requires a new untouched post-July 2026 holdout.

Acceptance criteria:

- Home regions are derived from current domestic-event metadata or earlier domestic history without hard-coded team mappings.
- Regional ratings update only after eligible cross-region results and complete timestamp groups.
- Unknown home regions produce neutral finite features and warnings.
- Simultaneous, ineligible, target, and future outcomes cannot enter regional features.
- Existing v3 candidates retain their exact pre-regional feature contracts.
- Regional candidates use the same chronological folds and fixed gates as their matched controls.
- Feature state and old pre-regional artifacts remain loadable.
- Results, diagnostic limitations, artifact purpose, commands, and checksums are documented in `docs/v4-regional-results.md`.

## Phase 3D - Nested model and feature optimization

Status: complete for development and shadow comparison.

The deterministic 300-trial search completed with zero failures.
Its nested selection policy did not improve primary log loss over the fixed v4 regional control.
The v4 model therefore remains the recommended shadow model.

Acceptance criteria:

- The exclusive pre-2026 cutoff is applied inside DuckDB for features and source matches.
- Four outer and three inner expanding-window folds keep exact timestamp groups indivisible.
- Fit-only preprocessing, calibration, identity vocabularies, and feature replay are tested.
- The deterministic schedule balances five families and cached or replay modes.
- A single-writer SQLite registry supports safe resumption and rejects contract mismatches.
- Logistic, histogram-tree, CatBoost, Elo-CatBoost, and dynamic Bradley-Terry families run.
- All 300 real trials finish or the 12-hour timeout records a balanced prefix.
- The finalist is locked from inner results before outer scoring.
- Pooled outer results include log loss, Brier, ECE, ROC-AUC, accuracy, breakdowns, and series-clustered intervals.
- A locked challenger can be refit as a self-describing development artifact and loaded in a separate prediction process.
- Results, limitations, commands, artifacts, and checksums are documented in `docs/v5-optimization-results.md`.

## Phase 3E - Hierarchical state-space strength

Status: complete for nested development evaluation and shadow comparison.

The preregistered policy improved the fixed v4 point estimate by 0.003024 log loss.
Its paired interval still crossed zero and its LCS slice narrowly failed the major-league gate.
V4 therefore remains the recommended shadow model, while the locked v6 blend is available only as a warned development challenger.

Acceptance criteria:

- The model protocol, priors, drift, update equations, candidate list, nested design, and gates are frozen before real evaluation.
- Gaussian latent state covers side, league, region, team, player, exact roster, role champion, patch-role-champion, and antisymmetric role matchup.
- Every latent prediction reads only evidence strictly earlier than its target.
- Complete timestamp groups update from one immutable pre-timestamp state.
- Reordering a timestamp group cannot change predictions or final latent state.
- Unknown entities receive neutral means and explicit prior uncertainty.
- Inactivity shrinks means and expands uncertainty toward component priors.
- The same state-space feature function serves historical replay and artifact prediction.
- Serialized and reloaded state produces identical probabilities and uncertainty.
- Existing v4 and v5 artifacts remain loadable and prediction-equivalent.
- The fixed v4 control remains on its original feature contract.
- Four outer and three inner chronological folds evaluate exactly five frozen challengers.
- The exclusive pre-2026 cutoff is applied inside DuckDB.
- Pooled results include all probabilistic metrics, breakdowns, series-clustered intervals, and fixed decision gates.
- A canonical finalist lock is validated before development refit.
- The development artifact embeds latent state and the lock, carries checksums, and warns that promotion failed.
- A synthetic study, refit, separate-process artifact load, and prediction run in automated tests.
- Results, limitations, commands, artifact, and fingerprints are documented in `docs/v6-state-space-results.md`.

## Phase 4 - Batch and live service hardening

Acceptance criteria:

- A batch JSONL interface and HTTP adapter use the same artifact loader and feature builder.
- Requests have explicit schema versions and idempotent prediction IDs.
- Artifact promotion is atomic and reversible.
- Staleness, unknown-entity rate, probability drift, calibration drift, and input validation failures are monitored.
- API clients implement timeouts, retries, rate limits, and response fixtures.
- No service logs contain credentials or full sensitive environment values.
- The service labels the result as a post-draft, pre-game-information estimate even when the broadcast is live.
- The service stores structured confirmed inputs and parser provenance rather than treating an image as an opaque model input.

## Phase 5 - Advanced modeling gate

Acceptance criteria:

- Baseline error analysis identifies a concrete limitation that representation learning can address.
- A neural or Siamese candidate uses the same chronological folds and point-in-time features.
- Equivalent team inputs share preprocessing and weights.
- The candidate improves mean log loss by a predeclared material threshold across multiple temporal folds.
- Calibration, robustness, inference cost, and operational complexity remain acceptable.
- If the gate is not met, the simpler promoted model remains in production.
